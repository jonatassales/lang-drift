# Development

The workspace uses pnpm and Turborepo to invoke each tool's native commands. Keep changes with the package that owns them and preserve unrelated local work. The rules every change follows live in `.claude/rules/`.

## Prerequisites and installation

Use Git, Node.js **24+** and the manifest-pinned **pnpm 12.4.2**. pnpm is the only package manager; another one fails on purpose. **Go 1.26+** is needed only for the `ex` CLI.

```sh
git clone https://github.com/jonatassales/tao.git
cd tao
pnpm install
```

Installation installs the Git hooks and links the `drift` launcher into your bin directory. It does not install a global CLI or modify shell profiles.

## Build and serve the docs

```sh
pnpm turbo run build --filter=docs...
pnpm --filter docs start
```

The build prepares shared dependencies, compiles Next.js, then indexes the documentation pages with Pagefind. Search assets are generated under `apps/docs/public/_pagefind/`; they are ignored by Git and restored with the build cache. Search requires a built index, including when using the development server.

For editing:

```sh
pnpm docs
```

The docs answer at `http://localhost:3002/docs`. Stop the foreground process when finished.

## Workspace commands

| Command | Purpose |
| --- | --- |
| `pnpm website` | Build the website's dependencies and start it on port 3000. |
| `pnpm console` | Start the console on port 3001 with its stub API, extub, on port 3401. |
| `pnpm docs` | Build the docs' dependencies and start them on port 3002. |
| `pnpm turbo run build` | Build every package that has a `build` script, upstream packages first. |
| `pnpm turbo run typecheck` | Run each package's type check. |
| `pnpm turbo run test` | Run each package's tests. |
| `pnpm turbo run check` | Run Biome format, lint and import checks on the whole repository. |
| `pnpm turbo run fix` | Same as `check`, writing safe fixes. |

## The drift CLI

`drift` is the repository's POSIX shell CLI. `drift --help` lists its commands: `setup`, `doctor`, `cleanup`, `reset`, `check dead-code|localization`, `env setup|validate` and `git setup|doctor|pre-commit|commit-msg|lint-history`. Run `drift check dead-code` after a refactor.

## Hooks and review

- **Pre-commit:** runs Biome on the staged files through lint-staged.
- **Commit-msg:** requires Conventional Commits, rejects AI signatures, and requires a `Ticket: <NNNN>` trailer naming an existing ticket when a commit changes `apps/` or `packages/`.

Work follows the spec-driven workflow: grilling, then a spec, tickets, implementation and code review. Specs, tickets and ADRs live under `.agents/workflow/`. Hooks provide local feedback, not approval; never bypass them.

## CI

GitHub Actions runs on every pull request into `main`, one job per concern: Build, Check (Biome, type checks and `drift check dead-code`), Test, and Guardrails (`drift git lint-history` over the pull request's commits). A local pass does not prove hosted CI success, and CI success does not prove production readiness.

## Source ownership

Docs routes live in `apps/docs/src/app/` as `page.mdx` files, ordered by `_meta.ts`. Nextra owns MDX rendering and navigation; the component mapping lives in `src/mdx-components.tsx`. Colors come from `@langdrift/tokens/docs.css`, and the mark from `@langdrift/web`.

No application secrets or backing service are required for the docs. They stay `noindex`; indexing them requires its own decision.
