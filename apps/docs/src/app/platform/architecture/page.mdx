# Architecture

The platform is built in one pnpm and Turborepo monorepo, code-named **Tao**. Each app is one deployable Next.js app; each package is shared across apps, never inside one.

## Workspace boundaries

| Location | Responsibility |
| --- | --- |
| `apps/website/` | The platform site served at `langdrift.md`: product pages, locales, metadata and the paused early-access flow. |
| `apps/docs/` | This documentation, built with Nextra and served under `/docs`. |
| `packages/tokens/` | `@langdrift/tokens`: design tokens built with Style Dictionary into one stylesheet per app. |
| `packages/web/` | `@langdrift/web`: shared React components, the icon family and the LangDrift mark. |
| `exphere/` | The Exphere workspace, the engine of Microruntimes: `@langdrift/ex`, the private Go CLI and the agent connected to the LangDrift console, and `@langdrift/exphere-contracts`, the Microruntimes contracts. |
| `platform/` | Repository tooling: the `drift` CLI, quality checks and the Git hooks. |
| `.agents/` | Project context, policies, and the specs, tickets and ADRs of the spec-driven workflow. |
| `.claude/rules/` | The rules that apply to every task in the repository. |

The `shell`, `account`, `runtime` and `contracts` packages are planned. Account and session will come from `packages/account`; the product switcher and the shell will live in `packages/shell`. No app owns them.

## Design tokens

Components use roles, never a raw color. Roles take shadcn's names (`background`, `foreground`, `primary`, `muted-foreground`, …). Each app imports one self-contained stylesheet built from the shared tokens and its app theme, which holds only the primary color and its hover state.

Status, classification, drift and rainbow colors are fixed across apps and never inherit a brand color. Dark is the default color scheme in every app.

## Package ownership

A package takes an app's name only while it has a single consumer. When a second consumer appears, it becomes a capability package under the `@langdrift/*` scope. Generic UI and the icon family have one owner in `packages/web`, so every app uses one identity; apps keep their business composition.

Package metadata does not demonstrate registry publication. Every package in the workspace is private.
