# SDD traceability rule

Local policy v1, requested and authorized through SPEC-GIT-HOOKS-SDD on October 11, 2026. Apply when preparing commits, reviewing changes, or delivering a PR. Criteria and evidence states are in the [SDD guardrail](../guardrails/0002-sdd.gr.md). The artifact tracker (consumer-owned reference: `../../artifacts/design/0006-DD-artifact-tracker.dd.md`) remains authoritative.

1. Associate each commit with exactly one ticket using a Git trailer, separated from the subject/body by a blank line:

   ```text
   feat: describe the change

   Ticket: HOOK-01
   ```

   Use the stable ID in the ticket's first heading (`# HOOK-01: ...`), not its filename number. Corrective commits may reuse a ticket. Ticket state does not determine whether the identity resolves; a hook never approves, closes, or rewrites an artifact.
2. A ticket declares one parent spec as `**Spec:** SPEC-ID v1 (consumer-owned reference: `../specs/0001-SPEC-example.spec.md`)` or `- Spec: SPEC-ID v1 (consumer-owned reference: `../specs/0001-SPEC-example.spec.md`)`. These are illustrative paths relative to a ticket directly in `.langdrift/artifacts/tickets/`; calculate links from the actual ticket directory. Specs declare their stable identity as `- ID: ` followed by a backtick-delimited ID. Missing, duplicate, ambiguous, or unresolved identities warn. These checks cannot prove that a change fulfills a ticket.
3. Associate each PR with one spec using `Spec: SPEC-ID` in the actual PR body. Review all included ticket relationships and the semantic change scope against that same spec. Report a missing declaration or mismatch as advisory evidence; do not treat a local candidate as an actual PR declaration.
4. Commit-msg reads artifact objects from the index; pre-push reads each outgoing commit tree. Uncommitted artifacts and working-tree corrections do not establish committed links. Pre-commit only reminds contributors to include the trailer because the message is not yet available.
5. Pre-push reports supplied ref ranges, deduplicates commits, and warns about inaccessible remote bases or shallow history. A new ref is assessed over all locally reachable history; this conservative scope can include previously delivered commits. No implicit fetch or hosted PR lookup occurs. Tag updates are reported separately; deletions introduce no outgoing commits.
6. Keep SDD findings and checker errors visible but non-blocking. Conventional Commit errors, staged lint failures, and failed build/test commands still block. A warning is not compliance, a human approval, or permission to bypass unrelated policies.

## Required code review and publication

For every implementation cycle, run the [code-review skill](../../workflow/skills/code-review/SKILL.md) before marking work done, committing, or pushing. Both Standards and Spec reviewers must examine the same identified source snapshot, including relevant uncommitted additions. Record their findings and outcomes in the originating spec/ticket; resolve actionable defects and refresh the affected review after material changes. A prior review is reusable only for the unchanged reviewed scope. A linter, test pass, or harness score does not replace this review.

Prepare a feature branch from `main` for reviewed changes. Each commit must identify its ticket, and each PR must identify its spec as described above. Use the configured author identity and publish only to the authorized destination. **Do not force-push**, including force-with-lease. If a normal push is rejected, inspect and reconcile the branch history without overwriting the remote. Commit/push authorization does not authorize unrelated changes or deployments.

This mandatory review procedure is an agent/contributor rule. The local hook does not run an LLM review or authenticate reviewer approval; its SDD evidence checks remain advisory. Record actual review evidence instead of claiming automated enforcement from this document.

## Local controls and limits

Developer setup and commands (consumer-owned reference: `../../../README.md#developer-checks`) describe installation and hook behavior. Pre-push supports a clean tracked tree at the outgoing checked-out commit; another source revision fails with a scope error. Do not stash, discard edits, or switch branches automatically. Untracked files are outside this tracked-source check; reviewers must verify the intended source and environment.

Hooks can be bypassed with `HUSKY=0`, disabled lifecycle scripts, or another hooks path. They provide local feedback, not server-side enforcement or authenticated approval. Remote publication still needs the user's authorization. Apply the [Dev workflow](../../workflow/dev/README.md) and record evidence for the actual inspected revision.
