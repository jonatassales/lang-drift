# `ex` performs the Microruntimes session and writes `.langdrift/`

**Status:** ready-for-agent

> **Note, 2026-11-05.** The owner closed 0105 as won't fix: 0225 (spec 0045) superseded it by bringing the runtime up before the first stage.

## Problem Statement

The Microruntimes page opens with a simulated `ex` session: a terminal types `ex agent plan <ticket>` and prints 43 lines, then `ex agent run` and prints 23 more, while four cards beside it, Ticket, Analysis, Plan and Workflow, fill in as the lines print. Spec 0014 brought the same four phases into the console as read-only listings fed by a stub. Nothing performs that session. The `ex` CLI still writes the layout it arrived with (`.langdrift/state/`, `.langdrift/runtimes/<id>/`, evidence outside the folder), `ex init` drops a 103-file scaffold of skills, templates, rules and a workflow proposal that LangDrift no longer prescribes, and no Go code knows a plan, a lap, a ledger, an episode or a judgement. The committed `.langdrift/` sample of ticket 0069 shows the files such a session should leave behind, and no code reads or writes them. A developer who wants to see the product do what the site shows has nothing to run.

## Solution

The website's session is the contract. Every line the simulated terminal prints becomes something `ex` really does, printed in the same words with true figures, and the four cards become records `ex` writes into the project's `.langdrift/` folder. The owner runs tickets by hand: `ex init` creates the folder, `ex harness` and `ex finops` record the guardrail inputs, `ex agent plan <ticket>` reads the ticket and the artifacts it links, follows their links under fixed limits, judges and extracts facts through a model, searches earlier runs with a structured RAG, resolves the components from their manifests, sizes them inside the envelope, checks the draft and writes the plan as the runtime file. `ex agent run <runtime>` executes that runtime once: it estimates and reserves against the team's budget, pauses at a gate or at a human stage, drives the owner's coding agent through the workflow stages, brings the microruntime up, observes the pull request, stops, settles the ledger and writes the memory the next plan retrieves. The plan file is the runtime file, and the runtime is the execution: one ticket, one runtime folder, one plan with revisions, one run with laps. The folder is gitignored; the committed sample becomes the CLI's golden fixtures.

## Implementation Decisions

- **The folder.** `.langdrift/` is gitignored at the repository root with an anchored rule, so the fixtures inside the CLI package stay tracked. It holds `config.json`; `microruntimes/AGENTS.md`; `microruntimes/runtimes/<id>/` with `runtime.md`, `run.json`, `run.md`, `laps/NNNN.lap.md`, `evidence/<execution>/` and the materialized native files; `harness/envelope.json` and `workflow.json`; `finops/budgets.json`, `gates.json`, `forecasts.json`, `prices/NNNN-<slug>.prices.json` and `ledger/<id>.ledger.json`; and the private `agent/state/` with the input records, the RAG index, the execution ledgers, Terraform state, build logs, connection records, credentials, the cluster record and the locks. `ex init` seeds no policy text: team-authored documents live in the team's tracker, linked from the ticket, because an ignored folder cannot hold them.
- **The plan file is the runtime file.** `ex agent plan` writes `runtime.md`: prose, the one `langdrift` fence the engine executes, and a `langdrift-plan` fence that holds the analysis and the plan (ticket, collection, sources, facts, inputs, discrepancies, retrieval, sizing, suggestion, components, totals, materialization, price, checks, state, authorization, contract gaps). The fence parser is unchanged: it counts only the `langdrift` fence. A replan raises the revision and is refused while the runtime runs.
- **The runtime is the execution.** The runtime id derives from the ticket's slug, DNS-label-safe, with an override. `run.json` records the execution: kind, state, outcome, window, laps with their choice, estimate, reservation, outcome and gate, stages with their state, confirmation, summary and usage, and delivery. `run.md` is the memory with a `langdrift-run` fence, the RAG's episode. Laps number from `0001`. An execution the connected agent starts without a plan gets a runtime folder with a `run.json` of kind `execution` on first start.
- **Records keep the sample's shapes.** Field order and json names follow the sample; a value not measured is `null`; arrays are never `null`; the illustrative flag is omitted by the CLI. A JSON formatter writes files with tabs, short scalar arrays on one line and Biome's layout as its fixed point, and fences with two spaces and small scalar objects on one line, because the standard encoder reproduces neither. Timestamps are RFC 3339 UTC to the second. Mirrors name `cli` as their source. The forecasts gain a planning entry so the planner's own calls have an estimate.
- **Collection is a deterministic shell.** Links are markdown links without a scheme, wiki links and `**Field:** path` lines, project-relative when they start with a slash, else relative to the linking file; traversal is breadth-first in document order with limits on depth, file count and total bytes; duplicates are recorded once at their first depth; secrets by name, symlinks and paths outside the project are refused and recorded; a binary is recorded by type, size and hash; the context hash is the sha256 over the sorted `path<TAB>sha256` lines with a trailing newline, as the sample records it. Prose never executes.
- **The judge is a port.** Three structured calls per plan: facts, verdicts and roles per source; relevance and reason per candidate episode; effort, model and reasons for the suggestion. The adapter uses the official Anthropic Go SDK with credentials resolved at the call, structured JSON outputs validated against the plan's schemas, and usage captured per call; each call is paid work: gated before the first call on the planning forecast, watched during, and written to the ledger's planning line. Without a credential or with `--no-judge`, the line says so once and the judged fields stay `null`. The planner's model is CLI input.
- **The RAG is structured and local.** The index holds one episode per earlier runtime: its ticket, title, stacks, component paths, measured flags, outcome, facts and vector. The default embedder is deterministic and offline, a hashed term-frequency vector over unigrams and bigrams with inverse document weighting, compared by cosine; the index records the embedder's id so a change rebuilds it. Retrieval takes the top six, drops below the threshold of 0.55, scores the structured criteria (same component path, same stack, measured resources, measured tokens) and keeps the judge's reason per candidate; sizing cites the kept episodes that measured resources.
- **Components come from facts and manifests.** Paths named by the facts or given as input are inspected deterministically: the manifest decides the technology (Go module, Node.js or Next.js package, NATS or Redis configuration, Python project, a Dockerfile), the port comes from the manifest or from a fact, the kind from the technology, and the proposed share from a sizing table by kind unless a fact states figures. The cross-checks are distinct ports, resolved images and allowed recipes, then the fence's own validation. The executed shares are the equal split the connected agent already applies, shared as one rule, and the difference is a recorded contract gap.
- **Money is deterministic.** The estimate is the forecast tokens by effort at the chosen model's list prices in cents per million tokens; the reservation is the estimate plus the margin, rounded up; the gates are the sample's FG-01 to FG-06: a price source that covers the model, an allocation for the ticket, no unacknowledged overspend, a reservation inside the per-run cap, the allocation and the period's remainder, a pause of paid calls when observed spend reaches the reservation or usage is unknown, and provisional billing. The ledger is rebuilt from the private run state at every change: a planning line, a line per lap, totals. FinOps types live in the CLI, not in the Microruntimes contracts.
- **Stages run in the client's harness.** The workflow input lists the stages with their skills and where a person takes part; a stage marked human pauses the run, with a prompt on a terminal and a confirmation command otherwise; the owner-only merge never runs. Each skill runs through a driver configured as input: an executable, arguments with placeholders substituted per argument, the environment variables to pass, a timeout, and where usage is read in the result; the driver is shaped like the hook executor (arguments, minimal environment, bounded output, no shell string), per ADR 0002. A stage may declare hooks, committed scripts allowlisted like recipes. The summary line comes from the agent's result.
- **The lifecycle is reused, not rewritten.** The run builds a local operator record (a local repository at the project root, the managed digests, the revision, the markdown) and drives the existing native adapter's materialize, start, observe and stop, so builds, claims, readiness, measurement windows and ownership-aware cleanup are the ones the connected agent uses. Evidence lands in the runtime folder, keyed by execution.
- **Delivery is observed.** The branch, the short commit and the upstream come from the repository; the pull request and its checks from the forge's CLI when it is installed, polled within a bounded wait; anything not observed is `null`. `ex` never pushes, opens or merges.
- **The session is an event stream.** One line catalog mirrors the website's terminal keys; the human renderer prints `agent ›` as the actor and the website's words with true figures; the JSON renderer prints one event per line with the website's line and reveal ids. The cards' header lines derive from the records as the console already derives them.
- **Commands.** `ex init` changes; `ex harness envelope|workflow|model|driver set`, `ex finops budget|gates|prices|forecasts set`, `ex agent plan`, `ex agent run`, `ex agent confirm`, `ex agent status` and `ex agent reindex` are new; the connected loop is renamed `ex agent supervise`; `ex agent connect|project|migrate|init`, `ex doctor` and `ex cluster` keep their behavior under the moved paths. Exit codes keep their meaning: a gate pause or a blocked check is a refusal; a missing ticket, input or tool is a missing prerequisite; waiting on a person is success.
- **Removed.** The embedded scaffold and its bootstrap; evidence under `.audits/`; the per-runtime `.env` and ignore file, replaced by credentials under the private state. Existing private state is not migrated; the README says to delete the cluster or the old state before upgrading.

## Testing Decisions

A good test observes what a user sees or what a file holds: the printed lines, the exit code and the `.langdrift/` tree, never a type or a function. The highest seam is the composed CLI: the composition root accepts injected ports (clock, id source, judge, embedder, lifecycle, stage driver, delivery observer), and one test reproduces the whole session in a disposable project seeded from fixtures, comparing the printed transcript with an expected one and the written tree with an expected tree, byte for byte, regenerated on request for review. The fixtures are the committed sample taken from the tree's history, the ticket 0070 with its linked sources frozen, and the expected output. Round-trip tests prove every sample file decodes into its type and re-encodes byte-equal through the formatter, pinning field order, names and `null` typing against the owner's reference. Unit tests sit beside each adapter only where an external system is faked: the collector in a disposable tree, the manifest inspector on sample manifests, the embedder's determinism, the gate arithmetic over the website's three-by-three model and effort matrix, the input store's previous-value chain, the driver and the delivery observer with a recording runner, the judge adapter against a local test server. No test reaches the network, a model, Docker, kind or Terraform.

Prior art: the composed-CLI tests at the package root that drive real adapters in temporary directories, the in-memory port fakes of the application package, the exact sorted file lists of the scaffold tests, the recorded-runner tests of the hook executor and the test-server coverage of the MCP client. Repository checks: the CLI's suite under the race detector, `go vet`, `pnpm turbo run check` and `drift check dead-code`.

## Out of Scope

- The server that answers the connected agent's protocol, and the console reading real records from `.langdrift/`; the projection from these records to the console's ticket phases is a follow-up spec.
- A provider embedding adapter; the local embedder is the first and the port stays open.
- Contract changes: canonical hashing of JSON records, per-component shares and technologies in the fence, a run-to-completion kind.
- Limits for parallel runs and run identity across branches.
- Pushing, opening or merging a pull request; the stages' skills do that in the client's harness.
- Changes to the website, to extub's generator or to the console.
- Migration of existing private state.
