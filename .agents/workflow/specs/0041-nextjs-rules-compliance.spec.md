## Problem Statement

The owner wants `apps/website` and `apps/console` to apply every item of `.claude/rules/06-nextjs.rule.md`. The read-only audit of 2026-11-04 measured the rule at 84% and found four classes of violation:

- **A second structure under `src/app`.** Both apps keep `src/app/lib/` with `components/`, `data/`, `views/` and `ui/` beneath it: 161 files in the website and 178 in the console. Item 3 lists what `src/app` holds (`template/`, `metadata/`, `api/`, `atoms/`, `state/` and "routes, layouts, pages, slots and the UI and data they own") and says new files do not invent a second structure; `lib/` is one, and 01-filesystem's rule 4 reads a directory named for a technical layer rather than a concern as a bucket. The aliases `@components/*`, `@data/*`, `@views/*`, `@ui/*` and `@event-testdata/*` in both `tsconfig.paths.json` files point into it, and the Biome import matcher lists them. Spec 0026 kept `lib/` for the console and spec 0027 kept it for the website except `state`; rules outrank specs (00-general, Authority 2), so both keeps are withdrawn. Modules that serve an API route sit in component folders: `apps/website/src/app/lib/components/early-access/` holds `request.body.ts`, `read-registry.compute.ts`, `turnstile.validation.ts` and eight more files that only `api/early-access/route.ts` and the book-a-demo interceptors import, and `lib/components/book-a-demo/book-demo-reply.response.ts` serves only `api/book-a-demo/`.
- **Route handlers that do not own their implementation.** Item 9 says a `route.ts` defines its HTTP methods and their dispatch directly and is never a forwarder. In the console, `api/console/[...path]/route.ts`, `api/console/products/[id]/executions/route.ts`, `.../history/route.ts` and `.../secrets/route.ts` export methods whose only statement is `return consoleHandler(request)`; the path check, the 404 and the upstream call live in `lib/data/console-handler.ts`. `api/console-stubs/[...path]/route.ts` declares a private `forward` that `GET` and `POST` call. In the website, `api/early-access/route.ts` exports `postEarlyAccess`, a 140-line handler beside the paused `POST`, with one `try` around the whole function, pure checks included, answering 503 to everything (00-general, External input and errors 6).
- **Proxy logic in `src/proxy.ts`.** Item 2 says the proxy's implementation stays in `src/proxy/`. The console's `src/proxy.ts` composes the Content-Security-Policy, chooses between the missing-screen rewrite and the locale middleware, hardens the locale preference cookie and sets the response headers inline; the website's is a 16-line delegate.
- **Files out of their place.** `apps/console/src/app/template/formatters/date-time.hook.ts` is a hook in the formatters folder, which holds one `.fmt` formatter per file. `apps/website/src/app/lib/components/website-header/language-pill.tsx` renders the language links as `<a href>` for an internal destination without saying why a full-document navigation is deliberate (item 6).

Until these are remediated, every app ticket of the other compliance specs would move or rename files that a later tree change moves again. That is why this spec's tree moves are prefactors every other spec's app tickets wait on.

## Solution

Both apps follow the tree of item 3 literally: `src/app` holds its routes, and the UI and data a route owns sit beside that route. `src/app/lib/` disappears from both apps. Each module moves to the folder of the nearest route segment (the locale layout, a route group, a page) whose subtree holds every file that imports it; the files of one concern move together into a folder named after the concern. The console's bridge to console-stubs, a service integration, moves to `src/infra/`. The aliases follow the tree, with names that say what they reach, and the Biome import matcher follows the aliases.

Every `route.ts` defines its HTTP methods with their dispatch inline and calls single-responsibility modules for the rest. The console's `consoleHandler` dissolves into the catch-all route; the console-stubs route inlines `forward`; the website's early-access `POST` owns its lifecycle behind an explicit pause, composed of interceptors and adapters like the book-a-demo route, with `try/catch` only around external calls. The console's `src/proxy.ts` becomes a delegate like the website's, and its implementation moves into `src/proxy/`. The date-time hook becomes a locale helper under `template/i18n/`, named after its export. The language pill navigates with the i18n `Link`.

Nothing a visitor or a console user sees changes, except that switching the website's language becomes a client-side navigation.

## Implementation Decisions

- **Placement rule.** A module leaves `lib/` for the folder of the nearest route segment whose subtree contains every file that imports it: the locale layout's folder for app-wide UI, a route group's folder for UI its layout composes, a page's folder for UI only that page composes. Modules of one concern move together into a folder named after the concern (`website-header`, `route-state`, `navigation`, `tickets`); such a folder may coincide with a route segment of the same name, which is then the owner. A folder beside a route that holds no `page.tsx` and no `route.ts` is colocation, as Next documents, and no `_private` folder is introduced because names stay kebab-case.
- **Website owners.** The locale layout owns the header with its parts, the footer, the skip link, the scroll-to-top, the structured data, the route state and the locale availability notice. The home page owns its sections and the platform hero. The `platform` layout owns the product-page building blocks. The FinOps page owns the FinOps sections and the FinOps illustrative content with the computes beside it; the Microruntimes page owns its sections, its content and the workflow model; the atoms and the catalog loaders import that content from its owner. The pricing page owns the plans section and the early-access section with its form, handlers, maps, state, types, validation, Turnstile controller, loader and types, and the registration fixture. The book-a-demo page owns its form, types, state, validation and positions. The book-a-demo API route owns its reply, the foreign-request validation, the addressed-origin compute, the field-errors compute and the error-code validation. The early-access API route owns its reply, the retry-seconds compute, the trusted-origin compute, the credential-free-origin validation, the challenge verification and the two environment-reading computes, which it keeps as they are until spec 0034 reshapes them. The JSON body modules both API routes share (the bounded body reader and its error, the plain-JSON check, the oversized-body check, the submission parser) move into one concern folder under `api/`.
- **Console owners.** The locale layout owns the route state, the error notice, the form styles, the account controls and the console API client: the console error, the request function, the read result, the mutation action, the resource hooks, the server read and the domain types with the entity-id and path-safety computes, which spec 0034 later splits by domain. The `(menu)` layout owns the navigation, the page focus, the source notice, the page heading, the status label, the dismissible-menu hook, the dialog hooks and the entity titles. The `(auth)` group owns the auth views. The `finops`, `home` and `settings` pages own their views. The `history` views, shared by the runtime and the product history pages, sit in the `(menu)` folder. The `runtimes` views, which the FinOps, history and product views also import, sit in the `runtimes` segment of `(menu)`, beside `[id]`; the stack icon and its JSON go with them. The `products` views sit in the `products` segment, and the `tickets` views, which the analysis, plans and workflows pages also import, sit in the `tickets` segment under the product. The `executions` views sit in the `executions` segment under the product.
- **The console-stubs bridge** (`consoleStubsRequest`, the base resolution, the host and cross-site checks, the hosted check and the server read builder) moves to `src/infra/console-stubs/`.
- **Aliases.** `@app/*` stays. The website gains `@layout/*` for the locale layout's folder, `@routes/*` for the `(pages)` group and `@api/*` for `api/`; `@components/*`, `@data/*` and `@event-testdata/*` go. The console gains `@layout/*`, `@auth/*`, `@menu/*`, `@product/*` for the product segment and `@api/*`, keeps `@infra/*` if present or adds it; `@views/*`, `@components/*`, `@ui/*` and `@data/*` go. The Biome import matcher lists exactly the aliases the two apps declare; the workspace packages are already in its alias group since spec 0044.
- **Console routes.** The catch-all console route defines `GET`, `POST`, `PATCH` and `DELETE`, each extracting the console path, refusing an unsafe path with the 404 reply and calling `consoleStubsRequest` with the `console/` prefix. The three product routes (`executions`, `history`, `secrets`) are removed because the catch-all answers them identically; the responses are unchanged. `readConsole` builds its server read and calls the bridge itself. The console-stubs route defines `GET` and `POST` with the allowed-path check inline, the allowed paths being a constant of the file. `consoleHandler` is deleted.
- **Website early-access route.** `POST` first checks an explicit pause value, a `.data` constant beside the route, and answers the paused 503 as today. Past the pause, it runs the interceptors (method, origin, content type, body size, body, schema) from an `interceptors/` folder beside the route, admits the email through the registry adapter, verifies the challenge, registers through the registry adapter, reads the receipt and replies. The registry calls live in one adapter under `src/infra/`, which takes the registry target (URL and key) as input so that spec 0034 decides where the environment is read, bounds the payload, composes the request signal with its own timeout and refuses redirects. `try/catch` wraps the registry calls and the challenge verification only. The route's unit tests call `POST` with the pause mocked off for the pipeline cases and once with it on. No module is left dead.
- **Console proxy.** `src/proxy.ts` keeps the matcher and delegates to one function in `src/proxy/` that composes the existing computes: the document policy with its nonce, the choice between the missing-screen rewrite and the locale middleware, the hardening of the locale preference cookie as one map, and the response headers. The locale middleware instance is a constant of that function's file. Behaviour, headers and cookie attributes are unchanged.
- **Date-time hook.** `useDateTime` moves to `template/i18n/` as `use-date-time.hook.ts`; the arrow function it returns is spec 0040's.
- **Language pill.** The language links render the i18n `Link` with the target locale, keeping the query string and hash suffix and the drawer-focus hand-off. The rendered `href` values are unchanged.
- **Detectors.** `drift quality check 06-nextjs` gains: a tracked-path detector for a `lib`, `components`, `views`, `ui`, `hooks` or `data` directory directly under `src/app`; an awk detector for an HTTP method in `route.ts` whose body is one `return` of another function; an awk detector for a function in `route.ts` that is not an HTTP method; a paths detector for a file under `template/formatters/` that is not a `.fmt` file; a line detector for `headers.set` or `cookies.set` in `src/proxy.ts`. Review-enforced, with no detector: an internal `<a>` whose `href` is computed; the ownership of a moved module; a framework file that lost its framework meaning.

## Testing Decisions

- **The existing suites are the behaviour seam.** `pnpm turbo run check typecheck test` stays green after every ticket, with `--filter=website` or `--filter=console` while a ticket is in progress and the whole repository before delivery. A move changes imports and nothing else, so a test that fails after a move points at a wrong import, never at a wrong expectation. Tests move with the module they cover and keep their file name; their descriptions belong to the testing compliance spec, not yet written.
- **The route tests are the route seam.** The console has no route tests today and gains none here beyond what the dissolution needs: the catch-all's 404 for an unsafe path and its forwarding are covered by a node test beside the route. The website's early-access route test exercises `POST`: the pause on, and the pause off for every refusal and the registry exchange, with `fetch` stubbed as today. The book-a-demo route test is unchanged.
- **The proxy tests are the proxy seam.** The console proxy's content-security-policy and matcher tests keep passing; the composed function gets a test for the cookie hardening and the headers. Prior art: `apps/console/src/proxy/content-security-policy.test.ts` and `apps/website/src/proxy.unit.ts`.
- **The detectors are the rules seam.** `platform/cli/drift quality check 06-nextjs` reports nothing in `apps/` at the end, and each new detector reports the pre-change tree's violations when run before its ticket's change, recorded as local evidence under `.audits/`.
- **Localization.** `platform/cli/drift check localization` stays green; this spec moves no catalog.
- A good test here asserts a response, a header, a rendered `href` or a detector finding, never the folder a module lives in.

## Out of Scope

- The environment-reading computes of the website and the console's policy-environment compute (spec 0034), empty catches (0034), one-function-per-file splits of `types.ts` and others (0034), file suffixes and the `@proxy/*` matcher entry (0039), `template.tsx` pass-throughs and the stack-icon duplication (0040), the website's `cn` formatter (0038), `../` in the console proxy test (0036), test descriptions (the testing compliance spec, not yet written) and the locale ids, `vi` and the Simplified Chinese fallback (the localization compliance spec, not yet written).
- Any change to what a page renders, what a route answers or what the proxy sets, beyond the client-side language navigation.
- A shared package for proxy logic between the apps.

## Further Notes

- **Colocation under route segments.** Item 3's tree reads "the UI and data they own" as ownership by a route, so this spec places modules beside their owning segment, with aliases that hide the `[locale]`, `(group)` and `[id]` segments from imports. The alternative, feature folders directly under `src/app` beside `atoms/` and `state/`, is not in the rule's tree and would duplicate route names (`src/app/finops` beside `platform/finops`). The owner may overturn the placement or the alias names at the pull request.
- **Three console routes removed.** The product `executions`, `history` and `secrets` routes forward to the same handler as the catch-all and would repeat its four lines; removing them changes no response. The owner may keep them, in which case each defines its methods inline.
- **Early-access kept behind a pause.** Spec 0027 left the paused early-access code for the owner to decide. Deleting `postEarlyAccess` would also orphan nine modules and their tests; this spec keeps the pipeline live behind an explicit pause value so that nothing is dead and the route owns its lifecycle. The owner may choose deletion instead.
- **Language pill navigation.** Switching language becomes a client-side navigation. The proxy still runs on the navigation request and writes the preference cookie, and skips prefetches as today; the drawer-focus hand-off, which assumed a remount rather than a reload, starts working as written. The owner may instead keep `<a>` with a comment stating that a full-document navigation is deliberate.
- **Early-access registry adapter and the environment.** The adapter takes the registry URL and key as input because spec 0034 owns where the environment is read; once 0034 reads them at the operation, the adapter is that operation.
