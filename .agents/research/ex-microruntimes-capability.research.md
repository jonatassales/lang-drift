# What the real `ex` reproduces of the Microruntimes hero, and what a console + extub microruntime needs

**Date:** 2026-10-28. **Question:** the Microruntimes page opens with a simulated `ex` session; which lines of it does the `ex` CLI in `packages/ex` reproduce today, and what does it take to run `apps/console` with `apps/extub` as a microruntime through `ex`? **Method:** every claim below was checked against the source in this repository at commit `e3041b4`, so its paths name that tree; the CLI has since moved to `exphere/cli`, with the fence and the protocol in `exphere/contracts` (spec 0010), and against the prebuilt binary `packages/ex/dist/ex` (version `0.0.0-dev`, built after the newest source file). Nothing was built, installed or started. The simulation lives in `apps/website/src/app/lib/data/microruntimes-content.ts`, `apps/website/src/app/lib/data/microruntimes-workflow.ts` and the `en.session.terminal` family of `apps/website/src/app/template/i18n/messages/microruntimes.json`; its spec is `.agents/specs/0007-microruntimes-hero.spec.md`.

Status vocabulary: **implemented** (the code does it), **partial** (part of it, or in another form), **absent** (nothing in `ex`), **by design** (the console, not `ex`, owns it).

## 4. The lifecycle the rest of the page describes

These are implemented, with the names the code uses:

- **One `langdrift` fence, prose never executed.** `Parse` requires exactly one fence, one JSON object, under 1 MiB (`configuration.go:61-84`).
- **Validate before any side effect.** `Validate` bounds identities, revision, envelope, model, effort, 1 to 16 components, and each component's path, image, port, readiness path and recipe (`configuration.go:93-145`). Recipes are a committed script named by a slash-separated relative path, or `docker build`, `go`, `npm`, `pnpm` or `make`; arguments may not be absolute, climb with `../`, carry `://`, or mount `--secret`, `--ssh` or `--build-context` (`configuration.go:160-213`; ADR `.agents/adr/0002-console-input-is-untrusted.adr.md`).
- **Prepare.** `kind` creates the project cluster and loads images (`packages/ex/src/infrastructure/kind/provisioner.go:70-101`); Terraform with the `hashicorp/kubernetes` provider runs `init -reconfigure` and `apply` for the namespace and its quotas (`packages/ex/src/infrastructure/configuration/terraform_root.go:19,267-268`; `packages/ex/src/infrastructure/terraform/preparation.go:96,128`).
- **Execute.** Builds run inside a disposable copy of the source: tracked and non-ignored files for a local binding, `.langdrift` and dotenv files excluded, 8 MiB per file and 128 MiB in total, with only `DOCKER_*` passed through (`native.go:334-431,827-892`; `local_source.go:155-200`). A docker recipe needs a `Dockerfile` in the component directory (`native.go:382-386`); a committed script resolves inside it (`native.go:399-405`). Each component becomes a one-replica Deployment named `c-<sha256(path)[:12]>` with a Service and an `httpGet` readiness probe, `imagePullPolicy: Never` (`native.go:109-126`; `packages/ex/src/domain/microruntime/native.go:107`).
- **Inspect.** `Observe` sums CPU and memory only when every running container has a sample, keeps the oldest timestamp and the per-pod windows, and leaves the rest unavailable (`native.go:461-545`).
- **Claims and leases.** A start needs a claim on the current intent version and revision; the lease starts at 15 s and follows the console between 5 and 60 s; events carry stable ids and increasing sequences and are acknowledged by id (`service.go:179,404-408,499-525`; `contracts.go:15-31`).
- **Cleanup by the ledger** and the private state under `.langdrift/state` (`native.go:432-438,667-718`).

## 5. Where the site, the docs and the code disagree

- **Evidence file names.** The site shows `validate.json`, `prepare.json`, `claim.json`, `inspect.json` and `cleanup.json` under `.audits/evidence/runs/exec-41b2/` (`microruntimes-content.ts:638-645`). The code writes `runtime.json` and `inspection.json` per run id, with `Billing: "unavailable"` (`packages/ex/src/infrastructure/storage/evidence.go:22-35`; `packages/ex/src/infrastructure/storage/layout.go:67-69`).
- **Guardrail path.** `harness/guardrails/…` on the site; `.langdrift/harness/guardrails/…` from `ex init` (section 2).
- **Install claim.** The `ex` README says installing the workspace runs `build.sh` (`packages/ex/README.md:24-28`); `packages/ex/package.json:4-8` declares `build`, `test` and `typecheck` only, and `.agents/context.md:11` says `pnpm install` never builds the Go packages.

- **Exphere leftovers in the console.** The connection instructions say "initialize Exphere" and "one .exphere folder" (`apps/console/src/app/template/i18n/messages/en.json:111,184`; `apps/console/src/app/lib/views/runtimes/connection-instructions.tsx:51-62`), while ticket `0006-rebrand-ex-to-langdrift` removed the name from `ex`.
- **Legacy descriptor still in the domain.** `domain/microruntime.Descriptor` is the JSON v2 format (`packages/ex/src/domain/microruntime/descriptor.go:13-19`); the connected agent generates it from the fence through `RenderBlueprint` (`packages/ex/src/infrastructure/configuration/connected.go:12-41`).

## 6. Facts that decide a console + extub microruntime

1. **Nobody in this repository serves the agent's protocol.** The agent POSTs JSON-RPC to `<console-url>/api/mcp`, HTTPS or HTTP on loopback, header `MCP-Protocol-Version: 2025-11-25`, Bearer credential; it calls `initialize` and `notifications/initialized`, then `tools/call` with `langdrift.project.sync`, `langdrift.project.bind`, `langdrift.bind`, `langdrift.sync` and `langdrift.claim`; responses are capped at 4 MiB and redirects are refused (`packages/ex/src/infrastructure/connected/mcp.go:30-45,52,72,84-90,144-170,172-213`). The request and response shapes are the structs in `contracts.go:15-161`. A grep for those tool names across `apps/` and `packages/ex/src` finds only `mcp.go` and its test. `apps/console` has routes under `/api/console/*` and `/api/extub/*` only (`apps/console/src/app/api/`), and `apps/extub` routes `/health`, `/probe`, `/webrtc/offer` and `/console/*` (`apps/extub/src/presentation/httpapi/handler.go:92-138`).
2. **`ex agent project` needs a project secret and a membership.** It requires `PROJECT_SECRET`, binds each runtime id the membership lists, and refuses a binding whose `runtimeUid`, `environmentId` or `projectId` differs from what it asked (`packages/ex/src/application/connected/project.go:14-16,100-117`). For a local binding, the repository path must be the canonical project root (`native.go:64-71`).
3. **Loopback guards on every hop.** The console forwards to `EXTUB_URL` only when the incoming Host is loopback and `EXTUB_URL` is `http` on loopback (`apps/console/src/app/lib/data/extub.ts:11-24`); server reads apply the same Host check (`apps/console/src/app/lib/data/server.ts:10-15`). extub listens on `127.0.0.1:EXTUB_PORT`, default 3401, and answers `403 local_only` to any other Host (`apps/extub/src/wiring.go:22-28,36`; `handler.go:26-34`). Its WebRTC offers only loopback ICE candidates (`apps/extub/src/infrastructure/rtc/hub.go:32-34`), so inside a pod the UI falls back to HTTP polling.
4. **One container per pod, no environment injection.** The generated workload carries image, port, readiness path and resources only (`native.go:109-126`; `packages/ex/src/domain/microruntime/workload.go:21-38`). Console and extub cannot run as two components; one image running both processes keeps every guard satisfied.
5. **Readiness without a loopback Host.** The kubelet probes with the pod IP as Host, so any path through the bridge answers 403. `/icon.svg` is a static route outside the middleware matcher (`apps/console/src/proxy.ts:21`; `apps/console/src/app/icon.svg`) and is the candidate readiness path; it has not been exercised.
6. **The repository root is a valid component path**, so one component can hold the monorepo build context (`packages/ex/src/domain/microruntime/path.go:65-70`). The tracked source is about 12.4 MB, under the 128 MiB limit.
7. **Images and build time.** No Dockerfile exists in the repository (ticket `.agents/tickets/0024-no-container-image.ticket.md`, decided for the website). `apps/console` has no `output: 'standalone'` (`apps/console/next.config.ts`). Each agent operation, build included, is bounded to 120 s and no caller sets `OperationTimeout` (`service.go:148-153`; absent from `packages/ex/src/wiring.go`). `kind load` repeats per start (`native.go:421-425`), so the image size matters.
8. **This machine.** `dist/ex doctor --json` on 2026-10-28 found docker 29.8.0, kind v0.33.0, kubectl v1.37.0 and terraform 1.16.5, reported `containerEngine: unavailable` (the daemon was not running) and no LangDrift project at or above the repository root.
9. **`ex init` writes into `.langdrift/`.** About a hundred scaffold files (agent README, three guardrails, three rules, eight templates, the workflow and 26 skills) land there, and `.langdrift/` is not in the root `.gitignore`.

## 7. Decisions recorded on 2026-10-28

The owner chose: drive the microruntime with `ex` directly, not through `drift`; build the server side of the protocol as a new app, `apps/exphere`, holding the real microruntime state while `apps/extub` stays a stub; compose one image with two processes, extub on `127.0.0.1:3401` and the console on `0.0.0.0:3001`; pre-warm the image build, the cluster and the image load before a start, inside the 120 s bound; share the fence and the protocol through a new `packages/contracts`; and let the CLI itself create the runtime and request start and stop, as a client of `exphere` with a credential distinct from the agent's. The plan file of the session holds the ticket outline; the spec-driven workflow owns the rest.
